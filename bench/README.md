# Shared benchmark harness

The client-side scripts every lane in this repo used to measure a running OpenAI-compatible server
(vLLM or SGLang) on host gracie. They are snapshots copied verbatim: absolute paths such as
`/home/jasonc/ds41f-exp/...` are where they lived on that host (see the top-level README).

## What we measure

| Benchmark | Script | Workload | What it reports |
| --- | --- | --- | --- |
| catid decode recipe | `bench_decode.sh` | 8,192 exact input tokens, 1,024 forced output tokens (`ignore_eos`), temperature 0, C warm-up requests then 5xC measured requests, per concurrency C | aggregate output tok/s, per-user tok/s p50 (1/ITL), TTFT, ITL, request latency, DSpark accept length |
| Cold prefill | `bench_prefill.sh` (wrapper) + catid's `bench_prefill.py` (not included) | unique uniform-random token ids per request, 1 output token, prefix cache reset before each point, 4 requests per (ISL, C) point | aggregate prompt tok/s, TTFT, GPU util and power |
| Knee sweep | `knee.sh` | short prose prompt ("Write a detailed paragraph about the number i..."), 192 output tokens, thinking off, C = 1, 2, 4, 8, 12, 16, two runs per C | aggregate and per-stream tok/s, mean of the two runs |
| GSM8K-200 | `gsm8k_eval.py` | last 200 GSM8K test questions, greedy, thinking off, 768 max tokens, 16 in flight | accuracy |
| Readiness | `wait.sh`, `waitready.sh` | poll `/health`; `waitready.sh` also fails fast on engine errors in the console log | - |

Units: every tok/s figure says whether it is per user or aggregate. "per-user tok/s p50" is the
benchmark's `output_tps_per_user_p50` (median over requests of 1 / inter-token latency).

## Where the numbers in a result file come from

`bench_decode.sh` writes one `c<C>.json` per concurrency (llm-inference-bench v0.4.29 format). The lane
tables read `results[0]` of each file:

| Column | JSON field |
| --- | --- |
| aggregate tok/s | `aggregate_tps` (completed output tokens / measured wall time) |
| per-user tok/s p50 | `output_tps_per_user_p50` |
| TTFT p50 | `ttft_p50` (s) |
| ITL p50 | `inter_token_latency_p50` (s) |
| request latency p50 | `request_latency_p50` (s) |
| accept length | `server_spec_accept_length` (from vLLM /metrics) |

`bench_prefill.py` appends one JSON line per point to `prefill.jsonl` (`agg_prompt_tok_s`, `ttft_p50_s`,
`gpu_util_mean_pct`, `gpu_power_mean_w`, `metrics_delta`). `knee.sh` writes `knee-<tag>.json` with
`rows = [[C, aggregate tok/s, per-stream tok/s], ...]`; only the mean of the two runs is stored.
`gsm8k_eval.py` writes `gsm8k-<label>.json` with the per-question results.

## Caveats

- With `--engine vllm`, `bench_prefill.py` resets the prefix cache through `POST /reset_prefix_cache`,
  which vLLM only serves with `VLLM_SERVER_DEV_MODE=1`. The Al-ENGR-style containers do not set it, so the
  call returns 404 (logged as `warn: /flush_cache failed`) and the cache is not reset. The prompts are still
  unique per request and seeded identically on every run, so a rerun of the same point on the same server
  hits the cache. Check `gpu_util_mean_pct`: one
  such rerun in the DeepSeek lane reports 119,827 tok/s at 0% GPU utilization and is invalid.
- The knee JSON keeps only the mean of two runs. At C12 and C16 the first run can include warm-up for
  batch sizes the server had not seen yet, which drags the mean down.
- `gsm8k_eval.py` here was last modified 2026-09-25 (after the DeepSeek-V4.1 GSM8K runs on 2026-09-24);
  the earlier revision was not kept.
- The scripts default to the ports and model names of the lane that wrote them (`PORT`, `MODEL_NAME`
  override them).
